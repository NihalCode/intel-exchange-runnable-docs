# Intel Exchange Runnable Docs — Agent Guide

This file is the authoritative reference for any AI coding agent (Cursor, Copilot, Claude, etc.) working on this repository. Read it before making any changes.

---

## Project Purpose

A Next.js documentation site for the **Cyware Intel Exchange (CTIX) REST API**. Every code snippet is runnable directly in the browser — users can fill in credentials, edit query parameters and payloads, and send real API calls without leaving the docs.

The source API documentation lives at `https://ctixapiv3.cyware.com/intel-exchange-api-reference/intel-exchange-api-reference` (Theneo-hosted SPA). The site's content was ingested from Theneo's Markdown export and vendored locally as JSON files under `src/content/pages/`.

## How Documentation Pages Work

1. `scripts/ingest.mjs` fetches the Theneo Markdown index and all per-endpoint `.md` files, parses them into structured JSON (`EndpointPage` or `SectionPage`), and saves them in `src/content/pages/`.
2. `src/lib/content.ts` (`allSlugs`, `getPage`) reads those JSON files at build time.
3. `src/app/docs/[...slug]/page.tsx` uses `generateStaticParams` to pre-render all ~530 pages at build time (SSG).
4. Pages with `kind: "endpoint"` are rendered by `EndpointView`; pages with `kind: "section"` use the `Markdown` component.

## How Code Snippets Are Rendered

**Central entry point:** `src/components/CodeBlock.tsx` → `src/components/runners.tsx`

1. `buildEndpointSnippets(page)` in `src/lib/snippets.ts` takes an `EndpointPage` and returns a `CodeSnippet[]` array (curl, JavaScript, Python, Request Body JSON, Example Response JSON).
2. Each `CodeSnippet` has a `runKind` field: `"http"`, `"json"`, `"javascript"`, `"python"`, or `"none"`.
3. `CodeBlock` renders the highlighted code and, below it, the appropriate runner from `SnippetRunner`.
4. For Markdown pages (section docs), `react-markdown` renders `<pre><code>` blocks — `Markdown.tsx` overrides those to use `CodeBlock` too, routing through `classifyRunKind` / `parseHttpSnippet` from `parse-request.ts`.

**Runner dispatch** (in `SnippetRunner`):
- `"http"` → `HttpRunner` — sends the request via the `/api/run` proxy
- `"json"` → `JsonRunner` — validates and pretty-prints JSON
- `"javascript"` → `JsRunner` — runs code in a sandboxed `<iframe>`
- `"python"` → `PyodideRunner` — runs code via Pyodide WebAssembly
- `"none"` with shell lang → `ShellNote` (non-runnable, shows info)

## How Runnable API Snippets Work (HTTP)

### Structured path (endpoint pages)

```
buildEndpointSnippets(page)
  └─ buildRunnableRequest(page)           → RunnableRequest {method, path, query[], headers[], body}
  └─ CodeSnippet.request = RunnableRequest
       └─ HttpRunner receives { code, request }
            ├─ QueryParamEditor   editable non-credential query params
            ├─ CredentialsForm    AccessID / Signature / Expires inputs
            ├─ PayloadEditor      editable JSON body (POST/PUT/PATCH only)
            └─ execute()
                 └─ resolveStructured(request, baseUrl, getCred, bodyOverride, queryOverrides)
                      → ExecRequest { method, url (full), headers[], body }
                 └─ POST /api/run { method, url, headers, body }
                      → { ok, status, statusText, headers, body, durationMs }
```

### Parsed path (Markdown snippets)

```
Markdown → CodeBlock → detectLanguage / classifyRunKind / parseHttpSnippet
  └─ HttpRunner receives { code }   (no request)
       └─ execute()
            └─ resolveExec(parsed, baseUrl, getCred, bodyOverride)
```

### Authentication

All CTIX Open API calls require three query parameters: `AccessID`, `Signature`, `Expires`. The `AuthPanel` in `AppShell` lets users input `AccessID` + `SecretKey`; `generateAuth()` computes an HMAC-SHA1 signature via the Web Crypto API and stores the result in memory via `RunSettingsProvider`. These values are injected at run time by `resolveStructured` / `resolveExec`.

## Extending Runnable Snippets

**Do NOT edit individual page files.** All changes must be made in the central components/lib.

### To add a new language runner:
1. Add a new `runKind` value to `CodeSnippet.runKind` in `types.ts`.
2. Implement a new runner component (see `JsRunner` as a template).
3. Add a case in `SnippetRunner` in `runners.tsx`.
4. Add detection logic in `classifyRunKind` in `parse-request.ts` if needed.

### To add a new snippet type for endpoints:
1. Generate the snippet text in `buildEndpointSnippets` in `snippets.ts`.
2. Attach a `RunnableRequest` if it's an HTTP variant.

### To add new editable fields to the runner UI:
- Edit `HttpRunner` in `runners.tsx`.
- For query params: update `QueryParamEditor` and pass overrides to `resolveStructured`.
- For headers: same pattern as query params.
- For body: update the payload editor section.

### To change how credentials are stored/injected:
- `RunSettings.tsx` — context provider, HMAC generation.
- `resolve-request.ts` — `applyCreds`, `credFieldsFromPairs`.
- `security.ts` — `isSensitiveName`, `looksLikePlaceholder`.

## Security Rules — Never Violate These

1. **Never store secret keys in `localStorage`.** `AccessID` may be stored (non-secret); `SecretKey`, `Signature`, `Expires` must stay in React state only (memory-only).
2. **Always mask secrets in output.** Use `maskText(text, secretValues)` from `security.ts` before displaying any request/response content.
3. **All outbound API calls go through `/api/run`.** The proxy implements SSRF protection (`assertPublicHost`), a timeout, and a response size cap. Never call external URLs directly from client code.
4. **JavaScript snippets run in a sandboxed iframe** (`sandbox="allow-scripts"` without `allow-same-origin`). Never use `eval()` or `new Function()` in the main app context.
5. **Always confirm before sending mutating requests.** `POST`, `PUT`, `PATCH`, `DELETE` require user confirmation before sending.
6. **Prevent XSS in output.** All response body text is rendered inside `<pre>` (plain text, no `dangerouslySetInnerHTML`). `highlight.js` output is safe (it escapes its own input).
7. **No hardcoded real credentials, tenant URLs, or secrets** in source files or git history.

## Testing

Tests live in `src/lib/__tests__/`. Run with `npm test`.

The test suite covers:
- `security.ts` — `maskText`, `isMutating`, `isSensitiveName`
- `resolve-request.ts` — `resolveStructured`, `credFieldsForRequest`, query string building, query overrides

Component tests requiring a DOM (runners, CodeBlock) are out of scope for unit tests; test those manually or add Playwright/Testing Library tests separately.

## Demo mode (no Cyware tenant)

This clone is meant to run snippets without a live tenant. By default `NEXT_PUBLIC_DEMO_MODE` is enabled (anything except `"false"`).

When demo mode is on and the request URL uses the placeholder host `tenantname.com` (from `DISPLAY_BASE` in snippets), `/api/run` returns simulated JSON via `src/lib/demo.ts` instead of performing DNS/fetch.

To call a **real** Cyware tenant: set `NEXT_PUBLIC_DEMO_MODE=false` in Vercel env, deploy, then enter the tenant base URL and credentials in API Settings.

## Deployment

- **Auto-deploy**: every push to `main` triggers a Vercel build.
- **Build command**: `next build` (configured in `vercel.json`).
- **Region**: `iad1` (Washington D.C., US East).

## Common Pitfalls

| Pitfall | Solution |
|---|---|
| `Could not resolve host: tenantname.com` | Demo mode is off (`NEXT_PUBLIC_DEMO_MODE=false`) but base URL is still the placeholder. Default is demo on: `/api/run` simulates JSON for `tenantname.com` URLs. Set a real tenant URL only when calling a live API. |
| `SyntaxError: Unexpected end of JSON input` in JS runner | The API returned a non-JSON body. The generated JS snippets use `response.text()` + graceful JSON parse — never call `response.json()` directly. |
| `npm ci` fails on Vercel with missing platform deps | Lock file was generated on a different OS. Remove the `installCommand` override in `vercel.json` (use Vercel's default install). |
| `reactCompiler: true` slows builds | Keep it `false` in `next.config.ts`. The React Compiler adds Babel to every file. |
| Re-running `ingest.mjs` hits HTTP 403 | Use `clean-local.mjs` to re-process vendored files without re-fetching. |
